# Dormant canonical replay pages

The Node session pipeline can materialize the complete canonical source union outside workerd. `SessionPipelineInputs.replayPages` and `SESSION_REPLAY_PAGES_ENABLED=1` select the optional stage; both default off. It follows pointer indexing in the existing event consumer and publishes through backend RPCs. A write, read-back, hydration or unexpected error fails the source event for normal queue retry. Outcomes that retrying cannot fix do not: a lost source race or lost publication CAS (`artifact_source_changed`, `artifact_publish_cas_failed`, `source_generation_changed`) is logged at info as `replay_source_superseded` (the newer source write's own event re-runs the scope), and a capacity refusal (SQLSTATE 54000, more than 10000 pointers, more than 256MiB/1M source records, the 2M-row/2GiB output bounds, an invalid canonical-timing value) is logged at warn as `replay_capacity_refused`. Oversize scopes are not yet handed to the #184 large-read path. The AWS stack refuses `transcriptStore.sessionPipeline.replayPages: true` until the reviewed normalized-prefix PutObject/KMS grant is wired. No live configuration, deployment, credential or grant is changed by this source implementation.

## Artifact v1

`src/session-read-api/canonical-artifact.ts` is the shared producer/consumer protocol. Hashes are lowercase SHA256 of the exact stored bytes, without decompression or reserialization. JSON objects are UTF8. Every root/node/page is at most256KiB, row pages contain at most1000 rows, tree fanout is128 and maximum depth is4. Half-open ordinal ranges cover rows, bytes or UTF16 code units, according to the node unit. All nodes/pages carry canonical identity and generation; row trees also carry table/view. The root lists each table/view's exact count and range-tree reference, including explicit zero counts. Hierarchy keeps the root bounded for hundreds of thousands of realistic rows rather than collecting every page descriptor there.

Raw, replay and bounds event views use the authoritative shared projection. Replay retains all flat fields and only the native message_id under record.payload; bounds retains the existing identity/time fields. Legacy tables retain complete payloads and raw primary keys, including BIGSERIAL strings. Events sort globally by exact microsecond timestamp, event_id, machine_id and kind bytes. Legacy link IDs compare as integers, not lexicographic strings. Legacy coverage stays null unless the actual source stream contains a verified explicit coverage record. SQL-oracle timing is materialized only when legacy coverage is known.

Oversized replay content is an out-of-band JSON-string segment tree; JSON preserves every UTF16 unit, including lone surrogates. Adaptive segments have at most64KiB encoded JSON bytes and65536 UTF16 units. A maxContent reader can hydrate only the required prefix plus one unit; a full read also verifies the whole string's JSON hash. Oversized arbitrary nested arrays/objects use exact JSON-byte segments and a SHA-bound byte tree. User payload fields are never interpreted as codec sentinels. Mandatory non-content fields remain complete. The consumer must refuse a row exceeding its explicit assembly bound; segmentation is not permission to lift Worker memory limits or silently truncate fields.

Keys are under the lexicographically first live physical manifest's prefix:

`<physical-prefix>/normalized/read-projection-v1/<anchor-raw-chain-sha>/<artifact-generation>/<object-sha>.json|bin`

The anchor raw hash is deliberately present: existing exporter orphan cleanup retains normalized keys containing its current raw hash and erases older raw-hash generations with the prefix. A source mutation invalidates publication before later old-prefix cleanup. Immutable unreferenced objects after failed CAS are safe orphans; cleanup/deletion permissions remain a separate operational responsibility. Same-anchor-hash generations can remain unreferenced until a later raw-hash change; a safe generation GC/retention plan is still an activation dependency.

## Source capture and publication

The raw Worker's16MiB/100k/64-pointer boundary is unchanged. A separate trusted Node snapshot uses256MiB raw input,1M actual parsed records and at most10000 complete pointers. Actual source reads enforce chunk counts/digests, bounded decompression, canonical identity, admitted user ownership, optional catalog ETag, accepted_seq, per-origin revisions, tombstones, separate legacy domains and the full physical/canonical alias union through the same shared projection/fold. The Node ClickHouse/index metadata pass shares this 256MiB/1M boundary only while the replay stage is enabled (`SESSION_REPLAY_PAGES_ENABLED=1`); the default, live search path keeps its 64MiB/100k-event/500k-row limits; its full-source reconciliation and actual #171 acknowledgement precede replay publication. Output rows are capped at2M and unique stored artifact bytes at2GiB; exceeding a bound refuses publication.

The raw cursor source-generation helper is unchanged and exported. Artifact generation is explicitly domain-separated as SHA256 of JSON.stringify(["canonical-read-artifact-v1",rawSourceGeneration,epoch,sourceFingerprint]). Canonical artifact semantic changes require a version/domain bump. Cursors also bind indexSHA so rebuilt content cannot be mixed across pages.

`20261105020000_session_replay_pages.sql` adds backend capture/publication RPCs and a compact claim-bound read RPC. Source fingerprint is SHA256 over PostgreSQL's exact UTF8 JSONB text of the captured source snapshot; callers carry this opaque fingerprint rather than reproducing PostgreSQL serialization. Snapshot includes all live pointer tuples, physical/canonical identities, revisions, raw-chain digests, owners, storage/bucket/format/ETag/count metadata, persistent pending epochs and directory epoch/tombstone. A NO CYCLE global sequence drives persistent per-canonical-scope epochs; erasure/recreation and return-to-identical values cannot recreate an old epoch. Source-field updates invalidate publication; classifier-only writes do not strand artifacts awaiting an S3 event they never produce.

The producer hydrates and rechecks the captured union, writes immutable objects create-only, checks every put acknowledgement, then reads back and hashes every object. Only then may publish_session_replay_pages CAS the exact source snapshot/fingerprint/epoch under the same row lock acquired by source invalidation triggers. It also enforces the exact current anchor prefix and index-SHA key. A live, non-tombstoned directory row is mandatory at capture and publication. Hard directory deletion blocks even a newly captured generation while source pointers remain; recreation allocates a new epoch and rejects all old captures. Stale, erased, foreign-scope or incomplete work publishes nothing current.

session_directory_replay_pages(workspace,harness,session) derives org from the existing signed search-worker policy and grants that role only this RPC. There are no new table grants. It distinguishes authenticated absence (exists:false) from an existing source without current publication (exists:true,current:false). The latter must be503 in page mode. Current responses acknowledge exact identity, epoch, source fingerprint, generation, normalized prefix and index key/SHA/byte count. The Worker rechecks this acknowledgement after bounded hydration and has no raw/Neon fallback in selected page mode.

## History lineage (#230, migration 20261105026000)

`20261105026000_canonical_history_lineage.sql` re-creates, with `CREATE OR REPLACE`, `session_replay_source_snapshot` and the three history-gated replay RPCs `capture_session_replay_pages`, `publish_session_replay_pages` and `session_directory_replay_pages`. Once it is applied, the 020000 bodies of these functions are dead code. For a history-required scope (installed history authority with a `ingest_history_scope_current` row), the snapshot carries `history` (authority, mask SHA, record count, derived anchor key, `ready`) and capture reports the scope as `blocked`, so this Node producer returns `source_blocked` and writes nothing. Only the history ingest path (`session_history_capture`, role `bulls96_session_ingest`) unblocks a ready scope. Publication for such a scope then requires the transaction setting `relay_history.source_permit` (set by `session_history_source_lock` or `session_history_replay_publish`). The permit must match the identity, epoch, fingerprint, authority and mask, the history source must still be current, and the index object must be a live registered `ingest_history_derived_objects` row of that authority. Publication also uses a different prefix: `<derived-anchor-prefix>/derived/replay/<artifact-generation>/` (the anchor's `manifest.json` replaced by `derived/replay/<generation>/`) instead of `normalized/read-projection-v1/...`. Scopes that are not history-required keep the normalized prefix described above.

`scripts/check-canonical-replay-fences.ts` therefore mutates the 20261105026000 bodies (the epoch/snapshot CAS, tombstone and directory-presence clauses of capture and publish). Mutating the 020000 bodies tests nothing, because 026000 overwrites them.

## Resource and rollout dependencies

Current checked-in AWS pipeline policy grants List/Get only; it explicitly does not grant Put. The new source code does not alter that policy or the transcript key policy. Before any enablement, the operator must review/capture scoped PutObject on the read-projection normalized namespace, GetObject for read-back, and the bucket's applicable SSE-KMS GenerateDataKey/Decrypt permissions. No Delete, old-version access, raw overwrite, broad bucket write or other secret is required by this producer. The Worker needs only authenticated claim RPC and scoped Get for these artifact objects; its current raw-read credential/binding must be proven to cover that namespace and encryption, not assumed.

Apply the reviewed additive migration and exact ACL/boundary/role-verifier/generation union before enabling the producer, then prove its backend role can call only the intended RPCs. Current Lambda is Node24/3008MiB; the synthetic native-Node proof records total RSS/time including PGlite overhead, and does not establish deployed memory/latency. Capacity exceeding the Node budget requires a genuinely streaming producer or separately reviewed resource plan, never larger workerd source limits. With the replay stage enabled, the Node index shares the 256MiB/1M producer source bound; without it, the search stage keeps its original 64MiB/100k/500k limits. The combined offline proof verifies actual #171 readiness and emitted ClickHouse rows; a deployed execution-memory proof remains required.

The consumer's explicit page mode, deployed producer/consumer versions, complete replay/coverage, future legacy writer fence/redirection, new eraser-before-exporter ordering, obsolete-object reconciliation, full public adapter parity and the complete migration/ACL/bootstrap union remain separate activation gates. Rollback disables the page consumer and producer flags; immutable artifacts/publication metadata need not be deleted to stop traffic. No enablement is part of this change.

## Activation blockers (not merge blockers)

These do not block merging the dormant code. Each must be resolved, or explicitly accepted by the owner, before `replayPages`/`SESSION_REPLAY_PAGES_ENABLED` is enabled anywhere:

1. **No cross-generation dedup or cleanup under one anchor hash.** Every source epoch bump writes a complete new artifact set under `<anchor-prefix>/normalized/read-projection-v1/<anchor-raw-sha>/<generation>/` (`src/session-pipeline/replay-publication.ts`, prefix construction). Objects are not shared across generations, and nothing deletes the superseded sets while the anchor's raw hash is unchanged. Exporter orphan cleanup removes them only after the anchor's raw hash changes. Storage therefore grows with every epoch bump of a session. A generation GC/retention plan is required.
2. **Merged-session content outlives a sibling session's erasure.** A merged (canonical) session's artifacts, including content from other physical sessions in the union, are stored under the anchor session's `normalized/` prefix. When a non-anchor sibling is erased, its content stays in the existing artifact objects until the anchor's raw hash changes and old-prefix cleanup runs. Publication is invalidated at once (the source epoch moves), but the bytes remain. Erasure must reach these objects, by deleting or rewriting the affected generations, before activation.

## Offline proof

The proof uses synthetic PGlite and a new empty local fs directory, with no service credentials:

```
bun run --filter @relayhistory/object-store build
node --experimental-transform-types --import ./scripts/proof-typescript-loader.mjs \
  ./scripts/proof-canonical-replay-pages.ts --events 300001 --out <new-empty-local-directory>
```

It exports actual source records with content/native IDs/tool metadata/counters across machines, then invokes the actual producer and SQL publication. proof.json/claim.json contain only synthetic metadata. Real offline workerd reads must exercise these bounded page objects rather than embedding the whole fixture in the isolate. Focused source tests cover write/read-back failure, source races, owner/digest/revision/alias/deletion CAS, ABA, >64 pointers, workspace claims and absent-versus-unpublished semantics. Mutation controls and exact capacity results belong in the PR evidence; a green suite alone cannot establish omitted cases.
