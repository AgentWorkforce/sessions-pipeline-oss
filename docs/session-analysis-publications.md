# Dormant full v1 analysis cache prerequisite

Status: source snapshot, bounded codec, pointer publication and demand lease ledger are implemented. The default-off Node Lambda path and disabled schedule/strict plan inventory are wired. Bounded reconciliation/backfill is wired; the separately reviewed reliable all-transition source outbox dispatcher must compose before activation. This document does not authorize a deploy, credential capture, schema apply, grant or enablement.

The Node publisher uses a pure SELECT/CTE equivalent of the actual `read_session_analysis_v1` projection with 0031 overriding 0024. The approved existing source role has SELECT on the four source tables but no application-function EXECUTE; runtime does not need a new grant. Actual upstream functions are independent test oracles. Public request/job IDs, status/history, nested brief fields and result JSON are retained. The virtual v1 job ID remains the SQL-projected ID. Workspace safety uses real request brief_job_id/analysis_job_id contributors rather than looking up that virtual ID in the physical job table. Full identity is (org, workspace, provider, session); legal duplicate session IDs in another workspace or provider do not poison the selected history. Request workspace and the effective real job provider filter the projection before the 50-row history window. Missing/foreign contributor evidence masks the entire analysis result and marks only the affected request/analysis failed with workspace_scope_unverified or source_scope_unverified. An unlinked request can resolve through exactly one proven provider in its own workspace; absent or ambiguous evidence refuses with analysis_request_source_ambiguous, rather than guessing or silently dropping history. Turn evidence uses the shared public attribution contract: metadata provider, non-owner persisted source, known same-workspace event owner, then a unique same-workspace event provider. An untagged owner-only turn is explicitly unbound. An analysis explicitly omitted by 0031's superseded rule is not a contributor to the retained brief.

A source adapter uses REPEATABLE READ READ ONLY with a server statement timeout and separately read-only credentials. It emits UTC six-fraction snapshotAt and a SHA of the source MVCC snapshot ID. The exact canonical public envelope SHA is computed with shared analysisSnapshotJson; analysisGenerationJson fixes identity/source property ordering across PostgreSQL JSONB and RPC serialization. Generation binds payload SHA, source epoch/fingerprint, source snapshot time and snapshot ID. The real SQL not_found outcome is stored explicitly, never inferred from an empty exporter.

Every immutable object uses the existing canonical graph limits: roots/nodes/pages <=256 KiB, segments <=64 KiB, fanout 128 / depth 4. The wrapper is session-analysis-index v1 / canonical-analysis-graph-v1. Two raw tables hold private identity fields, numeric ordinal and untouched public payload. A table-specific numeric ordinal comparator preserves the SQL array subsequence order. Arbitrary large result objects use exact JSON blob segments; no public field is interpreted as a codec sentinel. Aggregate canonical envelope has an explicit 16 MiB refusal ceiling matching the selected public API bound (with a shared 64 KiB transport reserve), which is not a claim that 128 MiB workerd can assemble that amount. The actual 6.56 MB workerd fixture proves only that measured slice. Actual large-result and total-response memory must be measured before activation.

Supabase stores pointer metadata and demand metadata only. Publication requires a live non-tombstoned canonical directory, the complete current replay source epoch/fingerprint, a current unexpired backend lease nonce, immutable verified object refs, and source snapshotAt strictly newer than the prior publication. Equal timestamps allow only an exact idempotent retry; divergence refuses. A final wall-clock lease and snapshot-TTL check after the pointer upsert rolls back provisional writes that stalled beyond authority, including idempotent retries. Source snapshots older than 120 seconds or over 30 seconds in the future refuse. The read RPC returns current=false when missing/stale/source-invalid, and authenticates with the existing signed search-worker tenant/workspace policy. Claim timestamps use the same UTC6 Z serialization as the immutable wrapper. Consumer rechecks the exact original wrapper pointer/source/snapshot acknowledgement after hydration; no Neon fallback.

The narrow request_session_analysis_cache(workspace,harness,session) RPC is intentionally a permitted read-role side effect: it collapses demand for an already live canonical identity into one wakeup row. It grants no table access. Repeated calls are debounced 30 seconds and keep a 5 minute active demand window. The worker claims one 90 second random-nonce lease, heartbeats every 20 seconds, publishes through the same lease-bound CAS, then schedules the next refresh 30 seconds later. Expired/replaced/source-invalid leases cannot publish or finish. Erasure invalidates heartbeat/publication/finish; claim removes blocked wakeups. Failure stores only a bounded code and retries with a capped delay. The 30 second cadence is a target until runtime scheduler load/latency is measured, not a guarantee from these unit checks.

Backfill and source-change hints must enqueue identities and use this same leased runner. A one-off helper or raw S3 event hook alone is insufficient: analysis job/request transitions do not necessarily rewrite raw S3. Required remaining wiring includes a reliable all-transition legacy outbox hint, bounded reconciliation/backfill with durable continuation, and measured publisher demand/load. The disabled one-minute EventBridge source definition invokes two bounded passes near t=0/t=30 seconds; actual backlog/network/resource scheduling may exceed that target. No global per-read or global 30 second Neon scan is permitted.

New source-read credentials, Supabase backend RPC access, normalized-prefix scoped Put/Get and applicable KMS permissions, exact migration/ACL/bootstrap union and deployed reader/publisher versions need operator capture. Current Get-only raw credentials do not prove writes or new-prefix reads. Keys stay under the first current physical raw-hash normalized prefix so existing erasure/orphan rules apply; same-anchor generation retention/GC remains a separate activation dependency.

Offline tests vendor only the exact 0031 projection and 0024 read function as a SQL oracle from RHC 9ff3a285cf2d7ac617ad4a2a59ffc6931a60fecb. Runtime SELECT/CTEs are checked against those actual source functions, including 64 lifecycle combinations, history ordering/microseconds and no-EXECUTE source-role controls. The proof script uses only synthetic PGlite and FS objects; no real credential is needed.

The runtime pure SELECT contract needs no application EXECUTE grant. This was the old org/session projection; the new scoped 50-row windows can expose older namespace-specific rows, so this aggregate does not establish the maximum scoped envelope. Actual Node 24.21.0 producer head 4a3e08f772a86dd2ea4f0777df1ef92493ee5714 generated the immutable namespaces-node24-v7 fixture using a SELECT-only source role with application EXECUTE revoked, durable enqueue/lease, the actual refresh runner and JWT pointer claims. The largest envelope retains 5.4 million UTF16 description characters and 10,000 nested tools. Publisher phase took 0.456 seconds; peak process RSS 1,298,280,448 bytes includes two PGlite databases and is not a standalone Lambda memory measurement. Earlier exact source fixtures passed four actual offline workerd HTTP proofs: 106 objects / 6,560,358 bytes / maximum object 65,536 bytes, with full snapshot hash/fields, stale/future timestamps and final acknowledgement fences. Fresh namespace-fixture workerd composition is separately recorded by the consumer owner. This covers the measured slice, not a universal 64 MiB row assembly claim or future inputs beyond the selected aggregate API bound.

The final source review reproduced three publication authority defects before repair: insert and idempotent update could finish after lease expiry, and insert could finish after snapshot TTL expiry. Each now returns false and rolls back its provisional pointer. Twenty publication controls / 89 assertions and 55 schema/ACL/boundary controls / 453 assertions cover the repaired SQL, with root typecheck. Twenty-one guard-reversion groups produce behavioral assertion failures; duplicate early/final lease and generation guards are reverted together when testing that boundary.

A wakeup has a separate monotonic generation and remains persistent until a successful publication. Backend hints always advance it. Public reads remain debounced 30 seconds; they arm an interactive 5 minute window. A hint during build invalidates the lease generation for publication; finish cannot clear a newer hint, and a fresh publication from another lease cannot satisfy the current lease's finish. Active interactive scopes are claimed before background backfill.

The disabled 30 minute reconciliation schedule performs a bounded SELECT-only keyset scan over request/job scope keys, then enqueues every proven provider in each workspace through the same backend sink. A nine-row lookahead detects more than eight providers and refuses the whole key (reason namespace_fanout_bound) instead of acknowledging a truncated fanout. A deterministic per-key enqueue refusal (SQLSTATE 22023: a legacy row keyed by a physical session id that maps to a different canonical id, or an out-of-range scope) is logged with reason enqueue_invalid_scope and skipped. Three deterministic errors from `capture_session_replay_pages` (20261105026000), which the demand function calls, are refused the same way, matched by SQLSTATE plus exact message prefix: 55000 `replay capture: ambiguous canonical source` (reason enqueue_ambiguous_source), and 54000 `replay capture: pointer capacity exceeded` or `replay capture: metadata capacity exceeded` (reason enqueue_capacity_exceeded). 55000 `replay capture: source epoch missing` may be transient and is not refused. The refusal log carries only scope ids and the reason code. All of these are counted as refused and the cursor advances past them, so one bad key cannot block discovery of every later key. It self-invokes the next exact cursor using the existing role-bound asynchronous continuation permission only after the page's enqueue acknowledgements succeed. Any other enqueue failure fails the page, which is retried without advancing its cursor; repeats converge to the same scope wakeup. New keys before a cursor are discovered by the next periodic full round. Invalid/unbound or unavailable source scopes are counted and cannot manufacture a publication. Page scan exhaustion does not certify availability; per-session current claims and complete backfill evidence are separate gates.

Both schedule pairs are included in the strict optional plan inventory. Each permission is create-only and bound to the exact rule/account; enable/disable updates only schedule state and the guarded pipeline environment. Mixed brief/analysis rollouts, permission edits, replacements/deletes and unrelated store changes are refused. Source configuration is default off and no running rule was changed. A 30 second refresh is a target, not measured service capacity: each invocation has bounded batches/time, source queries have 15 second timeouts, and actual demand, backlog, network, ARM64 Lambda memory and source outbox dispatch must be measured before enablement.

Namespace validation includes isolated actual 0031 SQL comparisons for three legal namespaces sharing one org/session, foreign history beyond fifty rows, contributor provider mismatch, unlinked request ambiguity, public turn attribution without a job-provider fallback, complete reconciliation fanout and overflow refusal. Existing artifacts with overloaded persisted turn source labels require a controlled re-export using the corrected exporter; truly unbound turn sources remain a coverage gate. No production object was rewritten by this implementation.

## Activation blockers (adversarial review 2026-11-05)

Source: the [#245 adversarial review comment](https://github.com/AgentWorkforce/sessions-pipeline/pull/245#issuecomment-6660595141). This PR already fixes findings 1 (the #193 title cache is folded in), 2 (per-key reconcile refusals are logged and skipped), 4 (the readonly source secret field is validated only in the analysis branch, with the flag on), the `analysisCache: true` stack refusal and the fence gap for the second default-off guard. The items below are still open. Each one blocks setting `SESSION_ANALYSIS_CACHE_ENABLED=1`, enabling either schedule or lifting the stack refusal. None of them affects the live path while the flag is off.

- **Finding 3: reconcile re-arms every scope every 30 minutes.** The backend enqueue (the 20261105023000 demand function, `ON CONFLICT ... DO UPDATE` with `NOT p_interactive`) always sets generation+1, `must_publish=true` and `next_refresh_at=now`, and keeps `attempts`. This causes four problems:
  - A background publication goes stale after 120 s, because `session_directory_analysis_cache` requires `snapshot_at >= now()-120s`. A full backfill of about 5.4k scopes therefore produces snapshots that nobody can read.
  - Capacity is 2 passes x 10 jobs per minute, about 600 per 30 minutes, against about 5.4k scopes, so the backlog never drains.
  - It resets the retry backoff of sessions that always fail.
  - The generation bump invalidates any in-flight build. Probe P2: a hint that arrives mid-build gives `failed:1`, `last_error_code analysis_publish_cas_failed` and no publication.

  This needs a design change: background enqueue must not bump the generation or reset backoff for an unchanged source, and freshness must be decoupled from the 120 s interactive window.
- **Finding 5: failures that can never succeed are retried forever.** `analysis_response_bound`, `analysis_request_source_ambiguous` and `analysis_projection_invalid` (analysis-snapshot.ts, analysis-publication.ts) finish with an error code, but `must_publish` stays true. They are retried at most every 300 s, each time with a full source snapshot of up to about 16 MiB. There is no non-retryable classification, and finding 3 resets even this backoff. Oversize payloads are refused, never truncated.
- **Finding 6: a source change mid-build deletes the interactive demand row.** `finish` sees a fingerprint mismatch and deletes the wakeup. Probe P3: `{"failed":1,"lost":1}`, `wake:[]`. The demand is lost until the next read request or reconcile, the error is counted twice, and live sessions are the most likely to hit it.
- **Finding 7: no generation GC.** Every refresh writes a new object set, because snapshotAt and snapshotId are part of the generation, and nothing cleans it up. A crash between the S3 write and the CAS leaves orphaned objects. Generation GC is an activation dependency.
- **Finding 8: masked analyses keep foreign metadata.** When an analysis comes from an unverified foreign contributor, only `result` is nulled. `sourceFingerprint`, `attempts`, versions and timestamps are kept (analysis-snapshot.ts). Otherwise there is no scope leak: the SQL filters by workspace and effective provider, and the fences `namespace_workspace` and `namespace_provider` go red when those filters are reverted.
- **History lineage: blocked sessions never publish.** For a session blocked on history lineage, enqueue returns `accepted:false` without a row, claim deletes blocked rows and publish refuses them. That causes no retry storm, but such a session never gets a publication until the history-ready clear is handled. Handling it needs a schema change and handling in `capture()` (analysis-publication.ts).

### Tracked coverage gap (delta review 2026-11-05)

A 22023 `analysis demand: canonical identity required` refusal (20261105023000) is skipped, not translated. A legacy request/job row keyed by a physical session id that maps to a different canonical id therefore never enqueues that canonical id from this row. The canonical id is reconciled only if some other request/job row is keyed by it, or a read arms demand. Refused keys are logged at warn with reason enqueue_invalid_scope. Track this gap and measure it from those logs before relying on reconcile as complete backfill evidence. The scan's own refused classes are 22023 (enqueue_invalid_scope), 55000 ambiguous canonical source (enqueue_ambiguous_source), 54000 pointer or metadata capacity exceeded (enqueue_capacity_exceeded), and the provider fanout bound (namespace_fanout_bound). Every refused key is retried on the next full round.
